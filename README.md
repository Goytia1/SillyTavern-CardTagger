# CardTagger · 角色卡批量标签助手

给 SillyTavern 的扩展。用 AI 批量读角色卡、打标签、写回酒馆的标签系统，解决"卡片太多找不到也不好筛"的问题。

## 它实际做的事

1. 从你勾选的角色里，抽出**你指定**的那几个卡片字段（默认：角色名 / 描述 / 性格 / 场景 / 知识库关键词）
2. 连同一份**你自己维护的标签词表**一起丢给 AI，让它做选择题
3. 结果以表格形式列出来，**逐张可勾选、可删词、可手补**，确认后才写入
4. 写入 SillyTavern 的本地标签库 —— 也就是角色管理面板里那些能点着筛选、能当"虚拟文件夹"用的标签

读数全程不改任何文件，只有你按下「应用」那一刻才落盘。

## 安装

### 方式一：从 GitHub 安装（推荐，方便更新）

打开 SillyTavern → 扩展（积木图标）→ **Install extension** → 填：

```
https://github.com/Goytia1/SillyTavern-CardTagger
```

装完在扩展列表里搜 **CardTagger** 启用，之后更新直接点同一个按钮覆盖即可。

### 方式二：手动丢文件夹

整个文件夹放进 SillyTavern 的扩展目录（二选一）：

```
<SillyTavern安装目录>/public/scripts/extensions/third-party/SillyTavern-CardTagger/
```
或
```
<SillyTavern安装目录>/data/<你的用户名>/extensions/SillyTavern-CardTagger/
```

> 注意别放到 SillyTavern 的**根目录** —— 那里 ST 不扫，扩展列表里不会出现。

重启 SillyTavern（或刷新浏览器页面 `Ctrl+F5`）→ 扩展面板里搜 **CardTagger** → 启用。

## 关键概念：酒馆里其实有两套"标签"

这一步弄混的话，打完标签会发现"筛不出来"。

| | 本地标签 | 卡片内嵌标签 |
|---|---|---|
| 存在哪 | `settings.json` 的 `tags[]` + `tag_map{}` | PNG 的 `chara` / `ccv3` 数据块里的 `data.tags` |
| 能不能筛选 | **能**，这就是角色管理面板里点着用的那套 | 不能，只是元数据 |
| 导出卡片会带走吗 | 不会 | 会 |
| 写入代价 | 纯内存 + 一次落盘，几百张秒完成 | 每张都要重写 PNG，慢，且 ST 会重新编码图片 |

**默认只写本地标签**，够用了。想"标签跟着卡片走"再打开回填开关。

## 界面：面板与设置

打开方式三选一：聊天框输 `/tag-cards`；扩展设置抽屉里的按钮；首次启用后从左上角积木菜单进入。

面板分两个视图，**右上角齿轮 ⚙ 切到设置视图**，点「返回」或「完成」回到列表：

- **主视图**：选范围 → 开始分析 → 勾选 → 应用
- **设置视图**：下面这四块配置全在这里，改动即时保存

（扩展设置抽屉里只保留了一个入口按钮，所有设置项都已经搬进面板，不再占抽屉的空间。）

### AI 数据源

- **独立 API（推荐）**：填 Base URL / Key / 模型。推荐用便宜的小模型，几百张卡跑下来成本极低。支持任意 OpenAI 兼容接口（DeepSeek、通义、GPT-4o-mini、本地 Ollama/vLLM 都行），也支持中转站的额外请求头/请求体。
- **复用 ST 当前连接**：零配置，但串行且贵。角色多的时候别用。

填完点模型名旁边的 **「拉取模型」**，输入框就变成可下拉的 —— 直接选平台上的模型，不用手打。改完 API 地址或 Key 也会自动拉一次；点「测试连接」跑通后同样会自动补上列表。

模型名那一栏**仍然可以手打**（本地 Ollama、vLLM 或某些中转的私有模型名不在 `/models` 列表里）。

各平台的 `/models` 返回格式不太一样，解析器兼容 OpenAI / DeepSeek 的 `{data:[{id}]}`、纯字符串数组、Gemini 的 `{models:[{name:"models/..."}]}`，以及把模型名当 key 的 map 形态。

### 标签池

AI 的候选词表，每行一个。内置了约 130 个通用词（身份/关系/性格/题材）。三个快捷按钮：

- **导入 ST 已有标签** —— 把你现有的本地标签并进来
- **从卡片内嵌标签汇总** —— 把所有卡自带的 tags 扫一遍去重
- **追加成人分类词** —— 内置 NSFW 词表

混合模式下，AI 优先用池内词；池里确实没有时才申请新建，新建的会在结果表格里标成**橙色**，方便你事后统一审查合并。

### 读卡范围

决定喂给 AI 哪些字段，以及每个字段的字数上限。字段越少越省钱。

「知识库关键词」很值得留着 —— 角色卡作者通常在 world info 的 key 里塞了最浓缩的设定词。

## 推荐工作流

1. 先小规模试：范围选「按关键字筛选」或者直接全选，跑 20 张看看标签质量
2. 不满意就调**附加指令**，比如"不要用 CEO，统一叫总裁"、"涉及师生恋一律打师生"
3. 满意了再跑全库
4. 结果表格里点「只看新建标签」，检查一下 AI 造的词有没有近义词重复（比如"霸总"和"总裁"）
5. 确认无误 → 应用

**在你点「应用」之前，硬盘上的东西一个字节都没变。**

## 常见问题：模型没给出任何标签

失败行上点「看原文」，对照下面的三种死法处理（弹窗里也会直接把发送给模型的内容列出来，方便判断是卡面没抽到、还是模型不给力）：

| 原文长什么样 | 原因 | 怎么办 |
|---|---|---|
| 一段自然语言（「抱歉，我无法…」） | 内容审核 / 破限失败 | 换不过审的模型或中转；「附加指令」里弱化提示词，让它只做分类、不复述卡片内容；先只读「描述」字段试 |
| JSON 只写了一半（`{"pick":["总裁","骨` 就断了） | max_tokens 把 JSON 截断了 | 设置里把「单次最大 token」提到 800 以上 |
| **合法 JSON 但 `pick` / `new_tags` 都是空数组** | 模型「稳妥」交了白卷——看懂了格式却一个标签都不给（太保守 / 模型太弱 / 卡面敏感被软拒） | 见下 |

交白卷时扩展会自动重试并**逐次加码地「推一把」**（第一次讲道理、最后一次直接下达指令），通常第 2 次就能出标签。仍然白卷的话：

- 换更强的模型（小模型最容易交白卷）
- 「读卡范围」只保留「描述」，信息越集中模型越敢判
- 「附加指令」里补一句：`至少给出 1 个标签，禁止返回空列表`
- 在「看原文」弹窗里核对「发送给模型的内容」——只有寥寥几行说明抽取字段没选对或卡面是空的

## 关于回填卡片（谨慎）

打开「回填卡片内嵌标签」后，扩展会调用 SillyTavern 的 `/api/characters/merge-attributes` 逐张重写 PNG。

几点需要知道：

- **先备份 `characters` 目录**
- SillyTavern 写盘时会按你当前的头像设置**重新编码图片**（可能缩放），不是无损操作
- 只有 `.png` 支持回填
- 纯 V3 格式的卡会被服务端校验器拒绝 —— 这种情况下文件**不会被改动**，只是跳过
- 这个写入路径刻意绕开了 ST 的 `/edit` 接口，因为那个接口会强制把卡片降级成 V2 spec
